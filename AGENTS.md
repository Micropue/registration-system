# 虎虎校园跑登记系统 — Agent 指南

## Repo structure

```
app/          # Vue 3 + Vite 8 frontend (port 3000)
server/       # Python FastAPI backend (port 8001)
docker-compose.yml  # MySQL 8.0 + FastAPI
```

## Essential commands

```bash
# Start everything
docker compose up -d           # DB + backend
cd app && npm run dev          # Frontend dev server

# Frontend (app/)
npm run dev          # Port 3000
npm run type-check   # vue-tsc --build --force
npm run build        # gen-update-logs → type-check → build (swaps proxy port 8001↔8000)

# Backend (server/)
docker compose restart server   # After code changes
docker compose logs -f server   # Tail backend logs

# Full rebuild
docker compose down -v && docker compose up -d
```

## Architecture notes

- **Build quirk**: `npm run build` runs `scripts/gen-update-logs.mjs` + `scripts/update-proxy-port.mjs` which rewrites `vite.config.mts` port 8001→8000, builds, then restores it (dev port is always 8001).
- **API proxy**: Vite rewrites `/api` → no prefix via `vite.config.mts`. So frontend calls `/api/auth/login` become `localhost:8001/auth/login`. Also proxies `/media` and `/ws`.
- **Auth**: Token stored in cookie (`token`), no HttpOnly flag. Every protected request uses `Authorization: Bearer ${cookie.get('token')}`.
- **Database**: MySQL 8.0 on port 3308 (host) / 3306 (container). Tables auto-created on backend startup. Default admin: `admin` / `admin-123456`.
- **Backend code hot-reloads** inside Docker because `./server/src` is mounted as a volume. Just `docker compose restart server` to pick up changes.
- **No tests exist**. No unit, integration, or e2e.
- **CD**: GitHub Actions push-to-main deploys frontend via SCP (`app/dist/*` → `/www/huhurun-www/client`) and backend (`server/src/*` → `/www/huhurun-www/server/src`).
- **PWA**: registered with `prompt` strategy (`virtual:pwa-register/vue`). `useRegisterSW()` exposes `needRefresh` / `updateServiceWorker`. App shows forced-update `v-overlay` when `needRefresh` is true.

## Frontend conventions

- **API calls**: Use `ajax()` from `@/api/ajax`. `isFormData: true` for form-style POST (multipart). JSON body by default.
- **Auth header**: Manually attach `{ 'Authorization': \`Bearer ${cookie.get('token') || ''}\` }` where needed.
- **Snackbar**: Each page has its own `snackbar` reactive with `showMsg(text, color)` — do not centralize.
- **AppDataTable**: Shared component supporting client/server pagination, search, filter, and optional drag sort (`enableDragSort`). Pass headers with `searchable`/`filterable` booleans.
- **No `alert()`** — use snackbar only. (Also enforced in `app/AGENTS.md`.)
- **Admin pages**: `.table-wrapper { width: 90%; }` is the standard container pattern.
- **Router guards** (defined in `app/src/router/index.ts`): `requireDefault` (any login), `requireAdmin` (has any of the admin permission keys), `requireGuest` (no login).
- **Page title**: Set via route `meta.title`, formatted as `"{title} - 哆啦A梦（校园跑版）"` in `router.afterEach`.
- **Sidebar**: Functions from `@/config/functions.ts`, filtered by user permissions via `PERM_MAP`. Two groups: `mainFunctions` and `bottomFunctions`. Badges on functional areas show pending counts (for admin) + notification unread counts (for default role).
- **Update logs**: Auto-generated by `scripts/gen-update-logs.mjs` from `src/config/update-logs.ts` on every `npm run build`.
- **Chat unread badges**: WebSocket pushes `chat_unread` event → `chatStore.incrementUnread()`. No DB changes; purely frontend state.
- **Notifications**: Two top-right dropdowns — pending tasks (`/api/pending-items`) and notification messages (`/api/notifications`). WebSocket (`/ws/notifications`) pushes `notification_update` and `business_update` events in real time.
- **Route watcher** in `App.vue`: navigating to `/sign`, `/feedback`, `/recharge`, `/admin/registers`, `/admin/feedbacks`, `/admin/recharges` auto-calls `POST /notifications/read-by-types` to mark relevant notifications as read.
- **Announcement popup**: `fetchLatestAnnouncement()` runs on every route change. Tracks dismissed UIDs via `localStorage`.
- **PWA update check**: `checkForUpdate()` triggers SW update. When `needRefresh` is true, a persistent `v-overlay` blocks all navigation until user clicks "立即更新".

## Backend conventions

- **AccountService** (`server/src/account_service.py`) is a monolithic class — do not duplicate its logic.
- **API response format**: `{"code": 200, "msg": "Success", "data": ...}`. Helper: `api_response()` but converts `None` data → `[]`. Use `JSONResponse` directly when `null` payload is needed.
- **Auth middleware**: `require_perm(authorization, "模块", "操作")` returns `(session, error)`. Check `if err: return err`.
- **DB migrations**: Done via `try/except ALTER TABLE ADD COLUMN` in `_init_settings_tables()`. Never manual SQL.
- **WS chat**: URL is `/ws/chat/{registration_uid}?token=xxx`. Token sent as query param. Chat permission `"聊天"` is checked on both WS connect and `GET /chat/{uid}`.
- **WS notifications**: `/ws/notifications?token=xxx`. Pushes `notification_update`, `business_update`, and `chat_unread` event types.
- **Database module**: Extracted to `server/src/database.py`. Fallback constants (`localhost:3308` etc.) marked with `# 禁止修改`.
- **Python deps**: Only `fastapi[standard]`, `mysql-connector-python`, `openpyxl`, `python-multipart`. No ORM — raw SQL via mysql-connector.

## Permission group names (for require_perm)

`账户管理`, `账户组管理`, `订单处理`, `工单处理`, `APP配置`, `充值审批`, `新建登记`, `新建工单`, `充值申请`, `余额查看`, `公告管理`, `下属管理`, `日报管理`, `聊天`, `聊天室`, `调整侧边栏位置`

- **Standalone boolean permissions** (added to `PERMISSION_TREE` and `defaultPermissions()`): `"聊天"`, `"聊天室"`, `"调整侧边栏位置"`. Super admin gets them by default; other groups need manual assign.
- **"调整侧边栏位置"** gates the "修改功能顺序" sidebar item (drag-to-reorder, saved in `localStorage` key `sidebar_order_{username}`).
- **PERMISSION_TREE updates** auto-apply to the super admin group on restart; other groups don't auto-update.
